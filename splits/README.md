# Locked project active-fire partition

The three manifests are generated by `python scripts/materialize_splits.py`.
Training and validation come from the local 2017–2020 ROI CSVs and the pinned
upstream validation IDs. The test manifest contains 24 fixed `US_2021_*` test
events.

`validation_event_ids.txt` is the single canonical validation filename; do not
add a duplicate `val_event_ids.txt` alias.

Every training/evaluation run must record the SHA256 digests of these files and
the produced sample manifest. The test split is final-evaluation only; choose
Tversky alpha/beta and thresholds on validation data.

The manuscript and code use the same 24 held-out test events. Each `US_2021_*`
identifier is the event unit for per-event records and event-level bootstrap.
